# 三轴控制与证据契约

计算预算 `(T,N,E)`、可靠性 `(ε,1−δ)`、完整文件上限 `(Bmax,CRFmax)` 共同约束一个控制器。ε 为 `abs(predicted−actual)/actual`。`max_encode_fraction` 约束请求的视频编码秒数，暖窗口与中断工作计入；音频、全片预览、校验和组装都受同一墙钟截止时间限制并另记成本。

## 两种目标

默认连续 x264/MP4：短编码按 preset 的 lookahead 帧数和输出 FPS 补足未来内容，保留两秒前文，只测中央呈现包。初始化 SEI 单独计入，周期 I 补偿是经验候选。视频单轨从现有探针的 MP4 `stsz/ctts/stss` 等表外推容器开销；未知结构和音轨配置回退为经验模型。有限前文、场景切换、VFR 和历史 GOP 状态仍可能偏离完整导出。

显式独立分段 x264/fMP4：冻结整数帧计划，各段独立以 IDR 起始，保留实际 AVC 样本。已经编码的探针直接用于最终文件，不再尝试近似连续编码的内部状态。全片第一条音轨转为 AAC 一次，保留 priming 和尾部。固定容器满足

```text
file_bytes = init_bytes + video_payload_bytes + audio_payload_bytes + fragment_bytes
fragment_bytes = fragments * (32 + 64 * tracks) + 16 * (video_samples + audio_samples)
```

分段语义、约束和画质代价独立验收，不把连续文件当成它的真值。参见 [核心验收契约](core-acceptance.md)。

## 内容模型和计算调度

默认时间代表无需全片扫描。可选内容计划先完成 4 fps、96×54 的输出空间预览，提取每段平均梯度和相邻帧变化，进行最多三个内容分组。预览索引按源摘要、滤镜、工具链、线程和实际窗口缓存；成本包含源解码，低帧率仍可能漏掉极短事件。

代表数随可用探针和视频编码量预算调整。代表模型固定后，其余块按预注册种子不放回均匀审计。设 P 为代表、U 为剩余 M 块、A 为 n 个随机审计块，y 是实际段 payload，m 为代表模型：

```text
payload_estimate = sum(y[P]) + sum(m[U]) + M * mean(y[A] − m[A])
```

固定 n 下对独立段总量无偏，不等于每次结果准确或任意停止时具覆盖率。连续目标另有上下文和封装偏差。没有观察到短暂高熵事件时，低样本方差无法排除它。点估计与达到用户可靠性要求明确区分。

共享截止时间会终止完整子进程组并清理私有临时文件，操作系统清理可能产生小额超时。测得的转码成本指导是否直接完成；这种 admission 预测不是完成时间承诺。独立段补齐时复用既有段，连续模式的暖探针不能当成最终片段。

## 可靠性

| uncertainty.kind | 证据 | 达标条件 |
| --- | --- | --- |
| uncalibrated | 点估计及诊断方差 | 不认证可靠性 |
| trajectory_split_conformal | 冻结来源域中轨迹级边际区间 | 相对误差界满足请求；硬体积上限仍需实际文件 |
| exact | 已完成整个文件，实际大小和摘要核验 | 文件大小满足上限 |

schema 2 每个来源组的分数为所有注册候选、变体和采样前缀的最大绝对 log error。family 冻结完整编码配置、CRF 网格、模型版本、预览/上下文规则、种子、线程、工具链、视频编码量参数及有限前缀上限。完整注册需要冻结源块数，不能删除难前缀。免费缓存观测超出前缀上限时不继承证书。

95% 至少需要 19 个独立校准来源组才有有限区间。覆盖依赖声明域内的交换性，是边际保证，不是逐视频条件保证。当前没有合格业务校准包，7 个保留来源不足，保持 `uncalibrated`。schema 1 的旧策略包不校准新模型。

认证整数点从区间端点的调和点相邻整数中选最小最坏相对误差；保留模型原预测。宽区间也会明确拒绝目标。

## 硬体积与质量搜索

候选提议从实际观测拟合 rate–CRF 关系。完整文件才认证上限；估计值只提议工作。找到可行文件后继续在允许网格内尝试较低 CRF，预算或回调中断时保留已经验证的最佳候选。非单调大小不剪掉未测低 CRF。`best_verified` 只表示当前测得的最优；所有较低网格都核验后才声明网格内最低可行 CRF。CRF 不是感知质量保证。

## 身份、缓存与发布

推荐上传阶段用 `PreparedAsset` 完整 SHA-256 后封印 memfd，后续 FFmpeg 继承文件描述符读取相同字节。准备时间、内核存储和生命周期单列，不把它当免费冷启动。普通路径在初次摘要及读取边界核对 device/inode/size/mtime/ctime，并在最终结果前再次完整核验摘要；普通 A→B→A 修改也会被拒绝。这不是恶意并发写入的瞬时快照证明。

原生构建身份不能仅使用 `ffmpeg -version`：同 ABI 的动态 x264 改版可能不改变该输出。Linux 上启动 FFmpeg/FFprobe 零帧输入进程，读取实际 `/proc/PID/maps`，完整 SHA-256 核验加载的可执行文件和库；映射身份或文件内容在检查期间改变时拒绝。该成本及子进程清理服从请求 Deadline。缓存和校准 family 纳入新身份，旧指纹不会被继续使用。

缓存以源、构建、配置、线程、计划或时间窗和管线版本分开；完整分段文件还绑定段管线和具体计划。MP4 文件大小和 SHA、JSON 记录校验和都检查，拒绝残缺或意外修改。预览和整数帧计划有独立校验。缓存命中仍需 I/O，不是分布式事务或多租户资源治理。分段起点准入还检查实际首个解码呈现帧，避免某些容器的共同 `stream.start_pts` 掩盖真实 A/V 延迟；音频 decoder 已处理 priming，不重复补偿。

仅发布已经满足请求的 exact 产物：复制至目标目录私有文件，检查大小/摘要，再原子创建目标；拒绝覆盖已有文件。发布在分析预算外，CLI 另记录其成本及冷启动端到端时间。
