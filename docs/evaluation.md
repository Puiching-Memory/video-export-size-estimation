# 可复现评测与验收协议

## 当前可验证范围

比较同一个文件、相同导出配置、相同资源和时间预算下的文件大小预测。第一版限制为 Linux、libx264 CRF 23 / medium / 两个编码线程、MP4；对照实验移除音频以匹配视频大小基线。音频及滤镜由真实 FFmpeg 集成测试另行验证。

开发诊断集有七个程序生成案例和两个公开视频来源：静态、运动、持续噪声、短时噪声、CBR 输入中的短时噪声、交替噪声、图形画面、行人、动画。程序生成案例不能代表独立真实业务分布。已查看过的案例和以前的 Bunny / 尾部噪声实验均不能充当最终盲测集。

新增 [industrial-v1 语料](corpus.md)包含 24 个上游视频和一个 VFR 衍生，按 16 个来源组预先划分校准与测试保留集。它们的素材完整性验证与旧开发集的预测准确率结果分开保存。CTC 短片、长片、衍生案例及 HDR 边界需要分别报告；新素材尚未生成预测误差标签。

预测先写入 `predictions.jsonl`，所有预测完成后才生成参考文件并计算误差。控制器自己选择并付费执行的完整编码是有效证据，但必须标记为 `exact`，不能冒充低成本预测。

## 复现诊断实验

安装项目依赖、FFmpeg，以及 [ab-av1 v0.11.7](https://github.com/alexheretic/ab-av1/releases/tag/v0.11.7)。官方下载的二进制需要自行放到可执行路径。下载公开视频：

```sh
python benchmarks/fetch_sources.py artifacts/sources
PYTHONPATH=src python benchmarks/run.py prepare artifacts/corpus-v1
PYTHONPATH=src python benchmarks/run.py run \
  artifacts/corpus-v1/manifest.json artifacts/benchmark-v1 \
  --ab-av1 /path/to/ab-av1 --budgets 1 3 8
```

输出目录必须尚不存在。每个方法/样本/预算组合使用独立冷缓存，任务顺序固定随机化。生成视频取决于 FFmpeg 版本；manifest 记录源摘要，metadata 记录编码器版本、方法设置和代码摘要。原视频不随仓库分发。

同一开发集的体积约束实验（先完成上述预测实验，取得参考文件）：

```sh
PYTHONPATH=src python benchmarks/size_control.py \
  artifacts/corpus-v1/manifest.json artifacts/benchmark-v1/references.json \
  artifacts/size-control-v1 --budget 8
```

默认选择运动、行人、持续噪声三例，将上限分别设为 CRF 23 参考文件的 90%、70%、50%，限制 CRF 不高于 35、最多四个候选。参考大小只用于定义实验条件，不向控制器提供参考文件或缓存。控制结束后才测量导出相对输入的 PSNR；质量评测不计入控制器预算。PSNR 只描述像素误差，不代替感知质量验收。`--quality-only` 可以重测已有控制结果的质量，无需重跑调度。

可运行的方法：

| 方法 | 编码与估计策略 |
| --- | --- |
| `uniform` | 三段均匀位置、每段 2 秒，实际片段 MP4 字节数按时长外推；超时保留完成的片段估计 |
| `ab-av1` | 官方 `sample-encode`，三段 × 2 秒，关闭 VMAF 与缓存，实际执行官方算法 |
| `visual-residual` | 全片视觉分组、代表片段与随机残差修正，最多六段，不允许升级完整导出 |
| `controller` | 同一个估计器，并按预算决定是否完成可复用的连续导出 |
| `full-encode` | 直接完成整个导出，作为成本与精确结果的对照；超时没有估计 |

方法具有相同时间上限，不代表花费同样多时间。表中必须同时报告实际耗时；固定三段基线提前结束时，其空余预算不应解释为实现速度更慢。短视频上完整导出可能已经很便宜，控制器零误差必须结合完整编码成本理解。

共同的实际 MP4 完整导出作为真值。ab-av1 的内部片段容器和采样实现由官方工具决定，这些差异属于该基线在此导出任务上的系统差异，不是对其所有用途的排名。

## 必须同时报告的指标

- 所有请求中有结果的比例、异常/超时比例，以及所有请求中达到误差目标的比例；不能删掉失败请求再报告成功率。
- 在有点估计的请求上报告 median / P90 / 最坏 APE，同时给出分母。APE 为 `abs(predicted−actual)/actual`。
- 完成预测的实际墙钟耗时、相对完整导出的成本、累计请求编码量、峰值内存/磁盘；当前小实验未测量全部资源指标。
- 区间覆盖率、区间宽度、拒答率，以及选择性停止后的覆盖率；当前无真实校准包，不能报告该项已达标。
- 硬体积上限的最终产物超限率、在允许质量范围内找到可行结果的比例、总耗时、失败原因。
- 冷缓存与暖缓存分别测量；缓存结果不与首次计算混报。

## 达到 SOTA 和工业验收所需的证据

先冻结导出语义、硬件、输入范围与业务 SLO，再开始最终盲测。不能对所有编辑器、任意硬件编码器或任意滤镜给出一个没有边界的 SOTA 声明。

1. **按原始来源分组的数据划分。** 同一原片的裁剪、分辨率、CRF 和编辑变体必须在同一组。开发、校准、盲测三者分离；最终测试前冻结代码与策略。
2. **有竞争力的完整基线。** 除当前 ab-av1 和固定均匀采样，还需加入调好预算的自适应均匀采样、编码器 first-pass/lookahead、可复现的学习式码率模型及完整编码；公开调参预算及成本。
3. **三维运行曲线。** 多个计算预算 × 多个 `(ε, coverage)` × 多个体积上限，分别绘制误差、达标率、拒答率、质量损失和成本。使用按来源分组的置信区间，不用单个均值宣称支配全部方法。
4. **独立质量测量。** 体积控制的结果需测量 XPSNR/VMAF 或任务要求的感知指标。提高 CRF 换得更小文件本身不构成最佳质量证据。
5. **运行可靠性。** 长视频、VFR、复杂音轨、编辑后内容、被取消任务、崩溃恢复、并发竞争、容量限制和输入变化均需验收。明确成功产物和失败响应，统计尾部延迟与资源峰值。
6. **影子流量。** 在真实业务输入上只做观察性预测，与后来实际导出核对，校准域发生变化时降级或重校准。该仓库尚无真实用户流量证据。

验收目标应由实际业务选定。当前代码实现了三轴接口和部分机制，开发诊断实验用于发现缺陷，不能替代上述证据。

## 研究依据及比较边界

- [Covell 等，2016](https://doi.org/10.2352/ISSN.2470-1173.2016.2.VIPC-237)：利用神经网络与嵌入式 bitrate 模型优化转码质量目标。论文报告在其测试设置下，无先验转码时约 65%、使用廉价预转码后约 80% 的输出落在目标码率 ±20% 内；这不是任意编辑时间线的完整文件预测指标。
- [Boya Cheng 与 Yuan Zhang，2019](https://arxiv.org/abs/1908.02939)：x265 lookahead 驱动的 GOP 级 CRF–bitrate 建模，绑定具体编码器与实验范围。
- [Chunlei Cai 等，2022](https://arxiv.org/abs/2208.10739)：目标是 per-shot 感知质量稳定，不能直接用其质量命中率代替文件大小准确率。
- [ab-av1](https://github.com/alexheretic/ab-av1)：直接可复现的采样外推基线。
- [Av1an](https://github.com/rust-av/Av1an) 与 [VCA](https://github.com/cd-athena/VCA)：提供场景编码/质量搜索和内容特征方面的工程参照，本实验没有复现其完整系统。

检索还发现了 2022 年 DOI `10.1109/SCISISIS55246.2022.10001859` 和 2024 年 DOI `10.1109/IPTA62886.2024.10755681`。目前只核对到元数据，尚未复现，不能声称已经超过其结果。2026 年 DOI `10.2139/ssrn.6748998` 的对象是图像编码，不作为直接视频预测基线。
