# Confidence with overlapping prefix observations

This is a new source/theory-only protocol. It changes neither the existing one-panel predictions nor their primary methods. No media, new risk scores, complete development labels, decoder or encoder is accessed. The earlier confidence sequence assumes disjoint uniformly sampled GOP units; the earlier rank checkpoint requires near-census sampling. This protocol instead draws panels whose prefix observations overlap, charges their full query costs, and uses only newly revealed frame values in each statistical update.

Freeze one source, target/toolchain/profile, original paid-known mask and ledger, a finite panel library, every full input cost and certified per-frame AVCC VCL caps `U_f`. Initial known bytes are an exact offset. In inference, each panel Γ contains only original unknown frames; execution still returns and charges all its pictures, including duplicates and old pilot pictures. Unknown bytes are a fixed finite population, without exchangeability or a distribution model.

At each transaction remove only panels with no remaining unknown frame. Let P be that active pool and `q_f = number of active panels covering unknown f / |P|`. Every remaining frame must have positive q. Before drawing, require **the most expensive active panel** to fit the remaining cumulative budget. Otherwise pause without drawing any coin. Do not remove expensive panels or repeatedly draw until an affordable panel occurs. A later budget increase can resume the same evidence history.

Draw uniformly from P. Charge the full chosen cost before attempting its native execution. After validating the complete panel, let S be the byte sum known before this transaction, R the then-unknown frames and C their cap sum. From only the fresh observations compute

`A = sum_fresh y_f/q_f`, `K = sum_fresh (U_f−y_f)/q_f`.

For every fixed candidate **complete total T**, the true total has conditional expectations `E[A | past]=T−S` and `E[K | past]=C−(T−S)`. These hold with changing pools, overlap, arbitrary unequal caps and value-dependent prior exact census. They do not treat side pictures as independent samples. Two nonnegative factors are

`lower(T) = 1/2 + A/[2(T−S)]`, `upper(T)=K/[C−(T−S)]`.

At a true zero denominator, its numerator is also zero, and define the factor as one. Impossible candidates are excluded. Each cumulative product has conditional mean one under its own fixed true T. Allocate α/2 to each direction and exclude T on **any past crossing** of `2/α`. Ville gives joint time-uniform coverage at least `1−α`. Inversion requires only the martingales for the one true T; no extra union bound over every candidate total is needed. Do not reset wealth or relabel the old candidate as a new remaining total after a disclosure. Only the current S/C/q in the next factor changes.

Intersect both inverted tests with `[known_sum, known_sum + sum_remaining U]`. The prototype uses exact fractions and monotone integer searches. Add the exact paid-known offset afterward. The harmonic point and radius `(upper−lower)/(upper+lower)` are a separate certificate, not a replacement for a model point. Empty sets, incomplete transactions and violated cap/identity/duplicate checks cannot satisfy a request. All-zero verified census is exact. Coverage is unconditional over the complete policy, conditional on the frozen prior information; it is not a claim of 95% coverage among selectively issued/successful runs.

During a random pause, an affordable **exact prefix census** may disclose frames without multiplying either product. Choose its source query deterministically by greatest remaining cap-mass removed per full input cost, then lower cost/query ID ties. Charge its whole query, including repeated known pictures. Recompute the active pool and q afterward. The native driver must support that exact closure; the prototype accepts explicit synthetic values only. An increasing budget can eventually reveal all frames, where the interval becomes exact. The cost to exactness can exceed one full encode because repeated windows/future context are charged; compare that known source cost with an explicitly charged complete continuous census branch. No full encode, preparation, source decode, hashing or earlier pilot is free.

## Which bounds are actually available

The pinned CABAC proof in `native_cabac_byte_bounds.py` bounds a successful complete continuous 8-bit progressive I420, one-slice, one-thread medium encode with the declared static library and configuration. It includes VCL emulation prevention/NAL/AVCC prefix bytes and excludes audio, global SEI, SPS/PPS and container bytes. Geometry/type can be used under that scope. Planned ratecontrol QP is not automatically the actual spec slice QP. The 640×360 cap is roughly 3.93MiB/frame: it is finite but very loose. Valid local prefix observations must reproduce this same fixed target, not merely a nearby encoding; +48 input-margin and complete imported-state/clock correctness still require separate gates.

SATD, AQ, MBtree, source motion, fitted μ, observed sample maxima and prediction agreement currently give **no proved hard upper on each unknown target packet**. A tighter source-conditional cap needs an independently checked proof. A count of the actual quantized syntax/CABAC bins could supply one, but performing that codec work must be billed and is not a cheap source-only assumption. Imposing VBV or abort-on-size changes the target/export contract; successful sampled frames do not certify that unseen frames obey an invented operational cap.

For one panel the deterministic missing-cap interval is the immediate certificate. E-process evidence can improve it or continue across later paid panels, but it does not remove the loose-cap penalty. A late frame covered only by its GOP’s final cutoff has one-panel observation probability `1/L`. A transcript-based exclusion of a legal high value on all its miss paths cannot have 95% coverage when its observation probability is far below .95. This is a statement about the declared bounded population, not proof that a specific source’s physical x264 output attains that worst cap. Strong source constraints could improve it; no such cheap constraint is silently assumed here.

The new value is an executable continuation contract: q is recomputed after overlap/census, duplicate fees remain charged, budget pauses preserve the same fixed-T evidence, and extra compute ends in a verified exact result. A 20% request may remain unsatisfied. No actual usefulness, narrow interval or industrial latency has been demonstrated by this theory fixture.
